# Plan & decision log

## Goal
A complete, safe-Rust port of libopus v1.6.1 with every feature, verified bit-exact against the C
library, with conformance vectors, fuzzing, benchmarks and size comparisons.

## Phases

| Phase | Content | Exit criteria |
|---|---|---|
| 0 Foundation | workspace, oracle crate, conventions, range coder, math, SILK macros, docs | foundation tests bit-exact, all targets build |
| A Leaf DSP | kiss_fft/mdct, modes/tables/cwrs/laplace/rate, pitch/lpc, SILK tables/sigproc/NLSF, resampler, packet/extensions/repacketizer/mapping_matrix/mlp | per-unit differential tests bit-exact |
| B Mid-level | CELT bands/vq/quant/celt.c, SILK decoder, SILK encoder common (NSQ, VAD, ...), analysis | same |
| C Codecs | CELT decoder, CELT encoder, SILK FLP encoder + enc_API | same |
| D Opus API | Opus decoder/encoder, multistream, projection | encode bytes + decode samples bit-exact across configs |
| E Hardening | RFC vectors + opus_compare, ported libopus test suite, C ABI crate (+ run C tests against it), fuzzing, benches, size report, cross-platform CI | all green |
| F Optional features | QEXT (done alongside A–D), custom modes, fixed-point build (layers FX0–FX5, docs/FIXED_POINT.md), DNN (deep PLC, DRED, OSCE/BWE) | differential tests vs oracle built with the same options |

## Decisions

| ID | Date | Decision | Rationale |
|---|---|---|---|
| D-001 | 2026-09-25 | Oracle = vendored libopus **v1.6.1** (latest tag), compiled by `cc` in `opusorus-oracle`. | Pinned, reproducible, no system dependency; `cc` lets us pass exact flags. |
| D-002 | 2026-09-25 | Oracle flags: float, `OPUS_BUILD VAR_ARRAYS HAVE_LRINT(F) ENABLE_HARDENING`, **no intrinsics/RTCD**, `-ffp-contract=off`. | Scalar C with no FMA contraction has a deterministic op order that Rust can reproduce → bit-exact comparisons instead of tolerance-based ones. |
| D-003 | 2026-09-25 | Faithful function-by-function translation, C names kept. | Bit-exactness requires identical operation order; traceability to C for review. |
| D-004 | 2026-09-25 | Workspace: `opusorus` (lib, no_std+alloc, forbid unsafe), `opusorus-oracle` (test-only FFI, unsafe allowed), `opusorus-conformance` (differential tests), later `opusorus-capi`, `opusorus-tools`, `opusorus-bench`, `fuzz/`. | Keeps unsafe out of the product; C ABI shim needs raw pointers so it is isolated in its own crate with `// SAFETY:` comments. |
| D-005 | 2026-09-25 | `no_std` + `alloc`; `std` feature (default) uses platform libm via `crate::math`; without it the `libm` crate. | Bit-exactness with the oracle needs the same libm (glibc); `no_std` still supported. |
| D-006 | 2026-09-25 | Float build semantics ported first; CELT arithmetic written through `arch` macro-functions (`mult16_32_q15` etc.). | Mirrors C; leaves a seam for the fixed-point build (phase F). |
| D-007 | 2026-09-25 | Range coder split into `EcEnc` (&mut [u8]) / `EcDec` (&[u8]) + `EcCoder` enum for shared paths. | Rust borrow rules; decoding never needs a mutable packet copy. |
| D-008 | 2026-09-25 | Parallel porting by units with strict file ownership, each unit in its own git worktree, merged between layers. | Lets independent units progress concurrently without breaking each other's builds. |
| D-009 | 2026-09-25 | QEXT, custom modes: ported in the same pass as the code they live in, behind cargo features `qext`/`custom-modes`, tested against an oracle built with the same define. | The `#ifdef` blocks are interleaved with the base code; porting them later would mean re-reading everything. |
| D-010 | 2026-09-25 | DNN features (deep PLC, DRED, OSCE, BWE) ported last. | Off by default upstream and need downloaded model weights (~MBs); core codec first. |
| D-011 | 2026-09-25 | Fixed-point build ported as a later phase with its own oracle config (`FIXED_POINT`), not in the first pass. | Doubles the verification surface of CELT; float is the default build and what users need first. The oracle `fixed-point` feature was removed until then because `--all-features` would build a fixed oracle against float tests. |
| D-012 | 2026-09-25 | SILK `OPUS_FAST_INT64` 64-bit macro forms used on all targets. | Proven exactly equivalent to the 32-bit fallbacks (unit test), simpler and faster. |
| D-013 | 2026-09-25 | Clippy: `clippy::all` + `missing_const_for_fn`, `unwrap_used`, `expect_used`, `allow_attributes_without_reason` etc. at warn, CI with `-D warnings`. `excessive_precision`/`approx_constant` allowed crate-wide (verbatim C literals). | User requirements; literal-exactness needed for bit-exact output. |
| D-014 | 2026-09-25 | Commits: plain messages, no co-author/session trailers. | User instruction. |
| D-015 | 2026-09-26 | DNN weights: fetched by `scripts/fetch_dnn_models.sh` (upstream tarball + checksum), not committed. The Rust DNN features will embed a binary weight blob (produced with upstream `write_lpcnet_weights` format) via `include_bytes!` and parse it with the ported `parse_lpcnet_weights`; users can also supply a blob at runtime (`OPUS_SET_DNN_BLOB`). | 87 MB of generated C arrays would be unworkable as Rust source (compile time/size); the blob path is upstream-supported and bit-identical. |
| D-016 | 2026-09-26 | Opus HD (QEXT) conformance vectors from `media.xiph.org/opus/ietf/opushd_testvectors.tar.gz`, RFC 8251 vectors from opus-codec.org; both fetched by `scripts/fetch_vectors.sh`, gitignored. | Large (765 MB), public, versioned upstream. |
| D-017 | 2026-09-26 | C ABI: opaque handles are registry-backed (memcpy-safe) Rust objects; variadic `*_ctl` entry points are C glue (`csrc/ctl.c`) jumping via naked-function trampolines into non-variadic Rust exports. | Stable Rust cannot define C-variadic functions; glue keeps the exact `opus.h` ABI. |
| D-018 | 2026-09-26 | DNN weights are runtime blobs (like upstream `USE_WEIGHTS_FILE`); tests serialize the oracle's compiled-in weights to a blob. `osce` implies `deep-plc` (upstream coupling). | See D-015; keeps the crate small and compile times sane. |
| D-019 | 2026-09-26 | Cross builds of the C ABI crate use host clang (freestanding) for the ctl glue; only static libraries are verified without platform SDKs. | NDK/Xcode are not available on the build host; the Rust core is pure Rust and needs no C compiler. |
| D-020 | 2026-09-26 | Fixed point: cargo features `fixed-point` and `fixed-res24` (implies `fixed-point`) on `opusorus`, the oracle and the test/tool crates; **not additive** (replaces float, like upstream), incompatible with the DNN features (upstream configure refuses it: `compile_error!`). Float API kept on. `--all-features` is no longer a valid configuration: `just` uses explicit `float_all` / `fixed_all` feature lists. | Mirrors libopus; a runtime switch would double the code and could not be bit-exact with either build. |
| D-021 | 2026-09-26 | Fixed-point port is done incrementally: unconverted modules are `#[cfg(not(feature = "fixed-point"))]`-gated (reduced crate), shared code keeps one Rust name per C macro/function with per-build definitions (`arch/{float,fixed}.rs`, `mathops/{float,fixed}.rs`); shims declare `// oracle-build: float|fixed|any`. See docs/FIXED_POINT.md. | Lets FX units proceed in parallel without breaking either build. |
| D-022 | 2026-09-26 | Fixed macros mirror the *release* `fixed_generic.h` expansion exactly (arguments `impl Into<i32>` with C's casts, C result types, plain arithmetic where C overflow is UB), not `fixed_debug.h`'s narrower types. | Bit-exactness first; explicit `extract16` marks every implicit C narrowing. |
| D-023 | 2026-09-26 | `OPUS_FAST_INT64` follows the C per-target selection (64-bit forms on x86_64/64-bit/MIPS, 32-bit partial-product forms elsewhere); both forms are tested against C on the host. | `MULT32_32_Q31/P31/Q32` differ between the forms; matching libopus on each target is the contract. |
| D-024 | 2026-09-26 | Decoder memory: C stack VLAs become Rust stack arrays (zero-initialised; frame-sized CELT arrays in two sizes so 48 kHz frames do not clear the 96 kHz size), except the int16/int24 `out` and multistream `buf` (heap, grown on first use: a per-call stack array would be zeroed on every call). DNN states that only a loaded model touches are allocated when the model loads (`LpcnetPlcState::dnn`, the LACE/NoLACE union member and the BWE state on first use), and models are `Arc`-shared, the embedded blob's bound once per process (`OnceLock`, `std` only). `get_size` reports the measured steady-state footprint. | Upstream's 256 KiB `test_opus_api` bound with OSCE, C-like footprints; outputs stay bit-exact because the lazily allocated states are provably in their initial state until first use. |
| D-025 | 2026-09-26 | opusorus is consumed from the Rust ecosystem only. `opusorus-capi` stays as a verification harness (runs upstream C tests / opus_demo against the port) but is not a shipped product: no no_std rewrite, no size work on the cdylib. Size/perf work targets the Rust crate. | User direction. |
| D-026 | 2026-09-26 | Final completeness audit (787 C functions in 191 compiled sources checked: all ported, renamed, or dead/debug-only upstream code). Remaining upstream build options become cargo features in phase G: `float-approx` (FLOAT_APPROX), `disable-float-api` (DISABLE_FLOAT_API), `fuzzing` (FUZZING), `assertions` (ENABLE_ASSERTIONS), `disable-rfc8251` (DISABLE_UPDATE_DRAFT), `fixed-point-debug` (FIXED_DEBUG), `dnn-debug-float`, `osce-training-data`, and `lossgen` (opus_demo `-sim_loss`). Not offered: `--disable-hardening` (removes safety checks; the Rust port is always hardened), `rtcd/asm/intrinsics/check-asm/dot-product` (SIMD/asm selection; the port has no C SIMD), `SMALL_FOOTPRINT` (not a build-system option). | Parity with every user-selectable libopus configuration. |
| D-027 | 2026-09-26 | Phase G DNN options. `lossgen`: ported into the library as `opusorus::lossgen` (the DNN layer runtime is compiled for it in any build, float or fixed-point, as upstream allows) with its model compiled in as Rust tables generated from `lossgen_data.c` (`scripts/gen_lossgen_data.py`; ~9 KB of weights, not in the DNN blob, always compiled in upstream); `lossgen_load_model` still takes a blob; `rand()` is a caller-supplied closure (opus_demo shares its glibc generator). `osce-training-data`: the files go to the working directory like C, process-wide, unbuffered; I/O errors are kept and returned by `osce_training_data::close_all` (C would crash), which also closes the files (opus_demo calls it before returning). `dnn-debug-float`: runtime blobs decide (as with C `USE_WEIGHTS_FILE`); the feature constrains the embedded blob (compile-time check) and selects the oracle without `DISABLE_DEBUG_FLOAT`. | Faithful to upstream's behaviour while keeping the library `no_std`-clean and testable in-process. |
| D-028 | 2026-09-26 | `disable-float-api` requires `fixed-point` (`compile_error!` otherwise; the oracle build script refuses it too) and removes the float API exactly where libopus' 56 `DISABLE_FLOAT_API` sites do, including `src/analysis.c` + `mlp` (the encoder runs without tonality analysis). Oracle shims that need the float API carry `// oracle-requires: float-api` (left out of that oracle) or `#ifndef DISABLE_FLOAT_API` blocks; the differential suites exercise the float-API cases with 24-bit PCM in that configuration. | Upstream configure/meson accept the option in a float build but it does not compile (`FLOAT2INT16`, `celt_float2int16`, `opus_pcm_soft_clip_impl` are used by the float decoder); CMake only uses it with fixed point. Mirroring the refusal is clearer than silently switching to fixed point. |
| D-029 | 2026-09-26 | `fixed-point-debug` (implies `fixed-point`) ports `celt/fixed_debug.h` and `silk/MacroDebug.h` as replacement functions with the release Rust signatures and the C debug semantics (bit-exact with a `FIXED_DEBUG` libopus, which prints and continues). Diagnostics use libopus' text (location = Rust call site via `#[track_caller]`) and go through `opusorus::fixed_debug`: stderr with `std` (like C), or a per-thread handler (`set_handler`: collect, log, or panic as `FIXED_DEBUG_ASSERT`); without `std` only counted. `celt_mips` and the diagnostic count are per thread with `std`, global atomics without it. Functions calling the checking macros lose `const` in that build only (`const_unless_fixed_debug!`). | Faithful (same values, same checks and messages, same per-macro operation counts) yet usable from Rust: no global mutable fn pointer (forbid unsafe), no panics by default (C continues), and parallel test threads see their own counters. Exact whole-codec `celt_mips` parity is not a goal: C macros re-evaluate operands with side effects (the debug `MULT32_32_Q31` expands one operand three times). |
| D-030 | 2026-09-26 | Phase G, part `float-approx` / `assertions` / `fuzzing` / `disable-rfc8251`. **`fuzzing`**: the random draws use a reproduction of glibc's `rand()` (`opusorus::glibc_rand`, moved from `opusorus-tools`) with **process-wide state** (one generator per process, shared by all encoders and threads, spin-locked atomics so the crate stays `no_std` and `unsafe`-free), starting in the `srand(1)` state, because C's is global: a per-encoder state would diverge for multistream/projection encoders, alternately used encoders and `opus_demo`'s loss draws, which share the generator (the `opus_demo` port uses it in fuzzing builds and resets it at start like a new process); the QEXT decoder's `depth_std` draw is kept. Bit-exact with a `FUZZING` libopus on glibc hosts given the same seed; the port never touches the C library's own `rand()`. **`assertions`**: crate macros `celt_assert!`/`celt_sig_assert!`/`silk_assert!` (`debug_assert!`, `assert!` with the feature) replace the ported checks (Rust-only invariants stay `debug_assert!`); C checks the port could not keep as debug assertions (failing on inputs the unit tests use, or `celt_assert(0)` before a kept error return, the `compute_ebands` layout checks) are compiled only with the feature (`assertion_failure!`); the fixed-point `_release` math variants check again with it, so C-UB overflow paths (stereo LFE) panic where libopus aborts. **`float-approx`**: no effect (and no `compile_error!`) with `fixed-point`, as upstream accepts the combination. **`disable-rfc8251`**: conformance set = the RFC 6716 vectors (`opus_testvectors.tar.gz`, still hosted by opus-codec.org, `testdata/vectors/rfc6716`). | Bit-exactness with the oracle built with the same defines; faithful process semantics of C `rand()`. |
| D-031 | 2026-09-27 | Safe SIMD via `fearless_simd` 1.0 (MSRV 1.88 → 1.89). **Vertical only**: each lane runs the scalar operation sequence of the port on an independent butterfly/pair (same order, no FMA; only IEEE-exact identities `a+b == b+a`, `(-x)*y == -(x*y)`), so the float build stays bit-exact with the oracle. Units: the float FFT butterflies (radix 2/3/4/5, `celt/simd.rs`), the MDCT pre/post rotations and TDAC mirror, and the DNN products (`dnn/vec_simd.rs`: the int8 block sums are exact integers, computed in integer lanes and added to the float outputs per block as in C; float `sgemv`). NEON-only instructions (`smull`, `saddlp`) go through `fearless_simd::kernel!` (safe code; the crate stays `forbid(unsafe_code)`). Runs on the compile-time baseline token (`Level::baseline()`: NEON on aarch64, SSE2 on x86/x86-64, SIMD128 on wasm32 with `+simd128`), no runtime dispatch (keeps `no_std`, avoids x86 multiversioning code size); other targets (armv7, wasm without SIMD128, thumbv7em) keep the scalar code. Verified by the oracle suites on NEON plus an in-crate SIMD==scalar self-test that also runs under wasmtime with SIMD128 (`just test-wasm`); the SSE2 path is compile-checked only (no x86 host). | FFT/MDCT were the kernels where NEON-optimized C was ahead (1.09–1.26×); vertical SIMD gets the speed without giving up the oracle. |
| D-032 | 2026-09-27 | Opt-in cargo feature **`fast`** (float build; no effect with `fixed-point`): kernels may use FMA, reassociated SIMD reductions and integer accumulation across the int8 blocks of the DNN products (as upstream's NEON/AVX builds do), so output is **not** bit-exact with the oracle. Default builds stay bit-exact and keep the oracle suites. Interoperability is unaffected: Opus conformance is defined by the bitstream and `opus_compare` tolerance, and libopus' own SIMD builds already differ from its scalar build at this level. Verified by `just test-fast` instead of bit equality: fast kernels vs the reference kernels within error bounds (unit tests), the RFC 8251 vectors through `opus_compare` (and Opus HD through `qext_compare`), and cross-codec tests against the C oracle (C encoder → Rust `fast` decoder vs C decoder, SNR thresholds incl. PLC and DNN; Rust `fast` encoder → C decoder, quality vs the input within a small margin of the C encoder's). The bit-exact suites are never run with `fast`. | User request: speed beyond what bit-exact SIMD allows, where C's NEON builds are ahead (DNN, pitch search). |
